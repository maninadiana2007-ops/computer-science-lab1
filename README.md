## 1. Описание системы
Название: Aviasales

Ссылка: https://www.aviasales.ru/

Назначение: Aviasales — это метапоисковик и агрегатор, который нужен для поиска, сравнения цен и выбора самых выгодных авиабилетов по всем направлениям.

Целевая аудитория:

- Частные пользователи, планирующие личные поездки, отпуск и путешествия.

- Командировочные и сотрудники компаний, летающие в рабочие поездки.

- Люди, которые не любят пакетные туры от агентств и предпочитают сами собирать маршруты, покупать билеты на Авиасейлс.

- Молодые активные люди, которые следят за трендами, понимают специфический юмор бренда в соцсетях и легко покупают билеты онлайн.

- Те, кто часто меняет локации, работает удаленно и ищет самые дешевые или сложные составные билеты.

- Сотрудники компаний или предприниматели, которым важен оперативный подбор удобных по времени рейсов.

Основные возможности:
Поиск и сравнение авиабилетов от 2000+ авиакомпаний и агентств.

Фильтрация и сортировка результатов по цене, пересадкам, времени вылета, багажу и другим параметрам:
1) Календарь низких цен и карта направлений для поиска дешёвых билетов.
2) Подписка на изменение цены с уведомлениями (Избранное).
3) Покупка билетов напрямую через Авиасейлс или у партнёров-продавцов.
4) Личный кабинет для хранения всех заказов и документов.
5) Сохранение паспортных данных для автоматического заполнения при покупке.
6) Поиск и бронирование отелей, трансферов и туров.
7) Управление заказами: возврат, обмен, скачивание маршрутной квитанции.
8) Корпоративный сервис: оплата по счёту, закрывающие документы, управление командировками.

Выбранный сценарий: поиск билетов по маршруту.

В рамках сценария пользователь открывает сайт, вводит на главной странице параметры поиска, запускает поиск, выбирает подходящий рейс из результатов и переходит к оформлению и оплате билета.

Серверная часть Aviasales отвечает за операции, которые требуют обработки и хранения данных на сервере.

Точная внутренняя реализация серверной части недоступна пользователю, поэтому часть выводов основана на наблюдаемых сетевых запросах и поведении системы.
### 4.2. Передаваемые данные

При работе сервиса поиска и покупки билетов между браузером и сервером передаются различные данные.

## 5. Описание пользовательского сценария

### 5.1. Выбранный сценарий

Название сценария: поиск и покупка авиабилета на Aviasales.

Цель сценария: найти подходящий рейс по заданным параметрам и оформить покупку билета.

### 5.2. Последовательность выполнения сценария

#### Этап 1. Пользователь открывает страницу

Пользователь открывает сайт Aviasales и попадает на главную страницу с формой поиска билетов.

На этом этапе браузер загружает необходимые HTML-, CSS- и JavaScript-ресурсы.

#### Этап 2. Пользователь вводит параметры поиска

Пользователь указывает город вылета и город назначения, выбирает даты вылета и возвращения, количество пассажиров и класс обслуживания.

JavaScript обрабатывает ввод пользователя: срабатывает автодополнение (code_to_places.json), подгружается конфигурация (config?market=ru).

#### Этап 3. Пользователь запускает поиск

Пользователь нажимает кнопку «Найти билеты».

JavaScript обрабатывает действие пользователя и инициирует отправку сетевого запроса к API.

#### Этап 4. Клиентская часть взаимодействует с сервером

Браузер отправляет HTTP POST-запрос на /search/v3.2/results.

В запросе передаются параметры поиска: маршрут, даты, количество пассажиров, а также идентификатор поиска (search_id).

#### Этап 5. Сервер обрабатывает запрос

Сервер принимает запрос и выполняет необходимые операции.

Предположительно, сервер обращается к базам данных авиакомпаний и агентств-партнёров, агрегирует цены и формирует список найденных рейсов.

Если требуется сохранение, данные о поиске записываются в кэш.

#### Этап 6. Сервер возвращает результат

После обработки сервер возвращает клиентской части ответ в формате JSON с данными о найденных рейсах.

Ответ передаётся со сжатием zstd (заголовок Content-Encoding: zstd).

#### Этап 7. Интерфейс отображает результат

JavaScript обрабатывает полученный результат и обновляет интерфейс.

Пользователь видит список найденных рейсов с ценами, временем вылета и информацией об авиакомпаниях. Далее он может применить фильтры, выбрать рейс и перейти к оформлению и оплате билета.

## 6. Построение архитектурной схемы

### 6.1. Архитектурная схема

Для демонстрационного варианта была построена упрощённая архитектурная схема информационной системы Aviasales.

На схеме представлены основные компоненты:

пользователь;

браузер;

пользовательский интерфейс (форма поиска);

клиентская часть;

API;

серверная часть;

хранилище данных;

внешние сервисы.

Схема показывает направление взаимодействия между компонентами при выполнении сценария поиска и покупки авиабилета.

### 6.2. Взаимодействие компонентов

Основные взаимодействия в системе:

Пользователь выполняет действия в интерфейсе Aviasales — вводит параметры поиска и нажимает «Найти билеты».

Браузер отображает интерфейс и выполняет клиентский код.

Клиентская часть (JavaScript) обрабатывает действия пользователя — автодополнение, фильтры, запуск поиска.

При необходимости клиентская часть отправляет запрос через API — HTTP POST /search/v3.2/results.

Сервер обрабатывает полученный запрос — обращается к базам данных авиакомпаний и агентств-партнёров.

Сервер обращается к хранилищу данных — для получения информации о рейсах, ценах и наличии мест.

Сервер возвращает результат клиентской части — JSON с данными о найденных рейсах.

Клиентская часть обновляет интерфейс — отображает список рейсов с ценами.

Пользователь видит результат выполненного действия — список найденных рейсов, может выбрать подходящий и перейти к оплате.
